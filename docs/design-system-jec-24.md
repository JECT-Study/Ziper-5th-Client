# JEC-24 이후 디자인 시스템: 웹·WebView·React Native

**권고:** 브라우저와 WebView의 일반 화면은 현재 TanStack Start + Vanilla Extract를 그대로 쓴다. 네이티브로 표시해야 하는 UI만 별도 렌더러로 구현한다. 두 곳에 같은 UI가 실제로 필요할 때 **값으로 된 토큰 → 작은 공통 컴포넌트 계약 → 플랫폼별 구현** 순서로 공유한다. 브릿지에는 직렬화 가능한 데이터와 결과만 전달한다. 이 브랜치는 액션 시트만 구현하며 디자인 시스템 패키지 이동이나 신규 라이브러리 도입은 하지 않는다.

- 이슈: [JEC-24](https://linear.app/ject5-team6/issue/JEC-24), [JEC-19](https://linear.app/ject5-team6/issue/JEC-19)
- 조사 근거: Figma MCP로 [Components](https://www.figma.com/design/aofNB0TCRM7yMND4bLj0ih?node-id=488-2999)와 [IA+화면디자인](https://www.figma.com/design/aofNB0TCRM7yMND4bLj0ih?node-id=10-3) 트리를 조회했다. 아래 주요 노드는 상세 디자인 컨텍스트까지 확인했다. Figma 원본은 변경하지 않았다.
- 코드 기준: [웹 컴포넌트 목록](../apps/ziper-web/src/components/README.md), [웹 토큰](../apps/ziper-web/src/styles/theme.css.ts), [네이티브 테마](../apps/ziper-mobile/src/styles/unistyles.ts), [브릿지 계약](../packages/bridge/src/contract.ts). 인벤토리는 현재 소스의 재사용 경계를 기준으로 하며, 모든 Figma 상태의 시각 일치를 보장하지 않는다.

## 권장 패키지 경계와 도입 순서

1. **먼저 `packages/design-tokens`.** 실제 양쪽에서 쓰는 시트 배경·본문/위험 색·8/16/24 간격·타이포만 심볼과 값으로 추출한다. 단위 없는 숫자를 원천으로 두고 웹 어댑터에서 `px`/CSS 변수, RN 어댑터에서 dp/pt로 해석한다. 웹의 기존 `vars`와 `typography` export를 유지해 호출부를 거의 바꾸지 않는다. CSS 문자열인 shadow, fallback font stack, CSS env safe area는 공통 숫자라고 가정하지 않는다. Pretendard는 웹 폰트와 네이티브 폰트 등록/시스템 폴백을 분리한다. 그림자·스타일과 아이콘은 두 플랫폼의 사용처가 생길 때만 공유한다.
2. **두 번째 사용처에서 `packages/ui`의 명시적 `@ziper/ui/web`, `@ziper/ui/native` 진입점 검토.** 공통 루트에서 양쪽 렌더러를 재export하지 않는다. 공통 API가 필요한 컴포넌트만 별도 타입으로 공유하고 platform-only props는 그대로 둔다. `.web/.native` 자동 해석은 Metro, Vite SSR, Vitest, TypeScript가 모두 같은 엔트리를 고르는지 확인하기 전에는 피한다. 워크스페이스 의존성은 `workspace:*`, React/RN은 번들 중복을 막도록 대상별 peer로 둔다. 화면/라우터/브릿지는 UI 패키지가 import하지 않는다.
3. **Vanilla Extract의 새 패키지 경로는 기술 검증 후 결정.** 우선 웹의 `.css.ts`는 `ziper-web`에 남긴다. 웹 앱 이외의 실제 소비처가 생겨 옮길 때 Vite plugin이 워크스페이스 소스를 변환하는지, SSR이 Node에서 원본 `.css.ts`를 실행하지 않는지, Nitro 배포 CSS가 유지되는지 확인한다. 안 되면 웹 패키지가 CSS 결과물을 빌드/명시 export한다. Metro가 해당 CSS 경로를 방문하지 않고 RN peer/React 인스턴스가 중복되지 않아야 한다.
4. **아이콘은 허용된 이름과 원본 경로만 공유.** DOM은 기존 SVG/Vite, RN은 필요한 정적 벡터 렌더러나 번들 이미지 사용. SVG 파일 URL을 브릿지로 넘기거나 Figma의 단기 asset URL을 런타임에 의존하지 않는다. 버튼의 접근성 이름은 플랫폼별로 동일한 의미를 갖고, 아이콘 디자인과 모달 닫기 제스처의 구현은 독립적이다.
5. **브릿지는 UI 패키지 밖.** `sheetActionsV1`의 버튼 ID만 돌려주고, 도메인 처리는 호출 화면이 수행한다. 다음 네이티브 보드 사용자 흐름이 확정되면, 단일 입력/다중 선택을 지금 웹에 둘지 먼저 결정한다. 필요할 때만 새 capability와 엄격한 데이터 계약을 추가한다(예: 보드 선택 목록의 안정적 ID, 사전 선택, `confirmed(ids)`/취소, 결과 ID 포함 검사). 폼 검증·오류·권한·최종 변경 요청은 기능에 남긴다.

**패키지 분리 검증 기준:** 웹 SSR의 초기 스타일·hydration·Nitro 빌드 유지, 네이티브 iOS/Android Metro 번들 및 개발 빌드 유지, 브라우저/앱의 접근성 이름·취소·오류 의미 동일. 대표 소비처 Button과 액션 시트 한 개로 먼저 검증한다. 새 라이브러리 도입은 현재 구현이 네이티브 UX 요구(예: 재현되는 스크롤/드래그 충돌)를 충족하지 못할 때 제한된 PoC로 비교한다.
