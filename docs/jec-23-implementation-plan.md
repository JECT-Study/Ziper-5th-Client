# JEC-23 후속 구현 계획

## 결론과 조사 기준

새로 만드는 작업이 아니라 **기존 상세·수정 구현을 현재 디자인에 맞추고, 구매 완료·구매 목록을 실제 API로 연결하는 작업**이다. 상세·수정 UI는 먼저 진행할 수 있다. 구매 API의 운영 활성화와 삭제 동작은 아래 선행 확인이 필요하다.

- 클라이언트: `origin/main` = `e2d785f6eb26b73691d6de6f01aa44d59f4136b2`.
- 백엔드: `main` = `027743541d001e0375466340f6f34678fac3785d`. `develop`은 `main`보다 3커밋 뒤이며 앞선 기능 커밋은 없다.
- Linear: [JEC-23](https://linear.app/ject5-team6/issue/JEC-23) In Progress, 디자인 [JEC-34](https://linear.app/ject5-team6/issue/JEC-34) Backlog, 구매 API [JEC-79](https://linear.app/ject5-team6/issue/JEC-79) Todo·담당자 미지정. 세 이슈의 댓글에는 추가 결정이 없다.
- 이 문서의 비교 표는 구현 전 기준이다. 상세·수정·구매 목록의 로컬 검증 및 재현 방법은 [JEC-23 사용법과 검증](jec-23-product-detail.md)을 참고한다. 구매·구매 목록은 운영에서 비활성이다. **보드별 상품 제거·휴지통 이동과 보드 화면 변경은 JEC-22 범위로 보고 이번 작업에서 제외했다**(아래 1·PR 3의 조사 내용은 JEC-22 참고용으로 남긴다). Linear 상태와 Figma 디자인은 변경하지 않았다.

- 기존 수정 노드 `1025:11257`은 삭제됐고, 최신 [수정 시트 `1085:10015`](https://www.figma.com/design/aofNB0TCRM7yMND4bLj0ih?node-id=1085-10015)는 네 가지 입력 아래에 보드 체크 목록과 ‘새 보드 만들기’를 표시한다. 기존 보드 API로 이 흐름을 연결했다. 최신 시트에는 링크·이미지 편집 필드가 없다. ‘이미지 업로드 실패’ 주석 `1085:10012`가 가리키는 시트 `1085:10320`도 동일하며, 저장 후 상세 `1085:10663`에서 기본 이미지와 대체 안내를 보여 준다. 정상 수정은 완료 처리하되 이미지 조회 실패는 별도로 안내한다. 정상 수정에서는 기존 이미지를 유지하고, 그 이미지를 사용할 수 없는 경우에만 대체 도안을 선택하게 한다.

### 디자인 확인이 필요한 지점

1. **삭제 범위:** 최신 [삭제 확인 `1085:10792`](https://www.figma.com/design/aofNB0TCRM7yMND4bLj0ih?node-id=1085-10792)는 현재 보드에서만 제거하며 타 보드는 유지한다고 명시한다. 공유 저장·직접 링크에는 진입 보드가 없어 삭제를 표시하지 않는다. 마지막 연결만 남은 경우는 JEC-79 명세대로 휴지통 안내를 유지하며, 운영에서 실제 반영을 확인해야 한다.
2. **수정 범위:** 최신 시안에 맞춰 체크박스와 새 보드 만들기를 제공한다. 링크는 PATCH에 변경 필드가 없다. 현 시안에는 직접 업로드 입력이 없어 추가하지 않는다. 수정 후 이미지 표시 실패는 시안에 맞춰 처리한다.
3. **표시 정보:** 최신 상세는 소속 보드를 보여 주고 별도 저장 시점 가격 안내는 표시하지 않는다. 전체 상품명, 품절·판매 종료 상태, 이미지 폴백, 빈 값·오류 처리는 유지한다.
4. **앱 메뉴:** 최신 D-1 상세의 상품 관리 바텀시트를 앱 WebView와 브라우저가 공유한다. 기존 Back 레이어를 사용하고, 다른 기능의 네이티브 액션 시트는 변경하지 않는다.
5. **구매 목록:** 최신 시안은 카드 더보기를 표시한다. 더보기 메뉴의 항목은 확인되지 않아 연결을 보류했다. 수정은 상품 상세에서 열 수 있고, 구매 취소·삭제도 별도 명세 없이 추가하지 않는다.
6. **일반 보드 카드 바로가기:** JEC-79가 참조한 [카드 액션 메뉴 `584:2121`](https://www.figma.com/design/aofNB0TCRM7yMND4bLj0ih?node-id=584-2121)은 ‘이 보드에서 제거’를 표시하나 나머지 두 항목은 모두 ‘수정’으로 되어 있다. 기다리는 동안 D-1 공통 메뉴에 해당 제거 문구를 사용하고 상세의 수정·확인 UI로 연결했다. 카드 메뉴를 열거나 닫는 것만으로는 상세를 조회하지 않는다. 최종 메뉴 표시 방식·항목은 JEC-22와 확인한다.

## 3. 권장 구현 순서

### PR 1 — 상세·수정 UI를 현재 시안에 맞춤 (API 추가 없이 진행 가능)

- 공통 `HeaderSub`, `Button`, `ChipFilter`, `BottomSheet`, `Modal`, `showToast`와 기존 토큰을 재사용한다. 기능 전용 green/Noto 스타일과 상세 라우트의 Google Fonts 링크를 제거한다.
- 이미지 영역을 4:3으로 맞추고 원본 이동 버튼을 하단에 배치한다. OS 상태 표시줄·홈 인디케이터를 웹에 그리지 않으며 기존 safe-area·`viewportHeight` 계산을 유지한다.
- 범위 확인 후 수정 화면을 바텀시트로 바꾼다. 상품명·가격·태그·메모를 편집하고, PATCH의 보드·이미지·쇼핑몰 값은 최신 상세에서 보존한다. 사라진 보드 등으로 필수값이 깨진 경우 기존 보드 재선택 처리를 없애지 않는다.
- 현재의 제목 200코드 포인트, 가격 0~10억원 정수, 태그 1개 이상·각 6자 이하, 메모 100자 규칙을 유지한다.
- 수정 취소·시트 닫기는 상세 GET을 다시 호출하지 않는다. 성공 응답으로 상세를 갱신하고 공통 토스트를 띄운다. 결과 불명일 때만 상태 재확인으로 안내한다.
- 구매 기능은 기존 `api.purchases` 지원 여부로 계속 숨긴다. 미배포 API를 호출하거나 가짜 성공을 운영에 노출하지 않는다.

### PR 2 — 구매 완료·독립 구매 목록 연결 (로컬 구현, 운영은 JEC-79 대기)

- `ProductPurchases.complete`를 실제 구매 POST에 연결하고 요청 중 중복 클릭을 막는다. 기존 `Outcome`의 done/rejected/unknown 구분을 유지한다.
- 구매 목록은 상세 내부 상태가 아닌 독립 경로(제안: `/boards/purchased`)로 만든다. 보드의 구매 완료 카드와 구매 성공 경로를 같은 화면에 연결하고 인증 가드·직접 진입·새로고침을 지원한다.
- 실제 목록 DTO에 맞춰 요약 항목·페이지 타입을 정의한다. 상세 전체 타입에 억지로 맞추거나 누락 필드를 얻으려고 항목별 상세 GET을 호출하지 않는다.
- 2열 카드·정렬 4종·다음 페이지·구매 완료 칩·성공 토스트를 구현한다. 기존 `ProductCard`와 보드 스타일을 재사용하되 차이에 필요한 최소 변경만 한다.
- 정렬 변경 시 목록·커서를 초기화하고 이전 응답을 취소/무시한다. 목록 실패는 목록만 다시 조회하며 성공한 구매 POST를 반복하지 않는다.
- 구매 완료 후 뒤로 가기·보드 탭 복귀에서 카드/개수/구매 요약이 서버 상태로 다시 읽히도록 한다. WebView가 이전 화면을 유지하는 경우를 포함해 JEC-22 담당자와 확인한다. 전역 캐시나 새 상태관리 라이브러리를 먼저 도입하지 않는다.

### PR 3 — 삭제 및 보드 관리 연결 (JEC-22 범위, 이번 작업에서 제외)

아래는 JEC-22 담당자에게 넘길 조사 메모다.

- 전체 삭제와 현재 보드 제거를 별도 동작·문구로 구분한다. 현재 시안의 “다른 보드에는 남아요” 확인창에 전체 DELETE를 연결하지 않는다.
- 현재 보드 제거가 맞다면 검증된 진입 `boardId`와 JEC-79의 개별 제거 API가 필요하다. 직접 링크·공유 저장 진입에서 보드를 추측하지 않는다.
- 전체 삭제가 맞다면 30일 휴지통 안내를 사용하고, 성공 시 상세를 닫아 이전 목록을 갱신한다. 휴지통 목록·복구 UI(JEC-27)는 이번에 구현하지 않는다.
